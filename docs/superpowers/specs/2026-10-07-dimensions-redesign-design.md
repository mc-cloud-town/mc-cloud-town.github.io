# 「三個維度」改版設計規格

日期：2026-10-07
分支：`feat/dimensions-redesign`
定稿的設計稿：`docs/design-demos/dimensions-v2.html`（首頁）、`docs/design-demos/progress.html`、`docs/design-demos/members.html`、`docs/design-demos/inner.css`

## 1. 目標

把雲鎮工藝官網改成一趟「走過 Minecraft 三個維度」的旅程。首頁是電影式的預告片，內頁是可查、可篩、可分享的資料頁。兩者共用同一套字體、維度色與頁首結構。

成功的標準：

- 首頁與設計稿在 1440 寬、暗色主題下逐段一致（章節、文案、轉場種類、順序）。
- 捲動動畫只用 `transform` 與 `opacity`，在作品區到地獄入口這段，超過 33ms 的影格不多於設計稿的量測值（319 格中 13 格）。
- 繁中、簡中、英文三種語言都沒有缺字或未翻譯的鍵，而且三種語言遵守同一套設計原則（見 7.1）。
- 亮、暗兩個主題都可用，選擇跨頁保留。
- `prefers-reduced-motion` 開啟時沒有捲動驅動的動畫，所有內容仍可讀。
- 從 360 到 2560 寬的九個視窗尺寸都通過響應式檢查（見 4.4）。

## 2. 範圍

這次改版拆成兩期，本規格只涵蓋第一期。

**第一期（本規格）**

1. 設計基礎：設計變數、字體、主題、維度狀態。
2. 新的外框：頂列、頁尾、左側維度軌道。
3. 首頁：出生點、主世界、地獄、終界、重生點。
4. 進度頁（完整世界紀錄）。
5. 成員頁（完整名冊）。

**第二期（另寫規格）**

- 建築作品、紅石作品與作品詳情、開源、合作夥伴、硬體、加入、404。
- 內頁之間跨維度的轉場（傳送門、落下）。
- 網址帶語言的多語系路由。

**第一期不做的事**

- 不改 `static-data` 的資料結構（見 6.3 的過渡做法）。
- 不移除 antd 與現有元件；舊頁面維持原樣運作。
- 不改部署流程。

## 4. 設計基礎

### 4.1 字體

- 標題：昭源宋體（Chiron Sung HK），字重 700、900。
- 內文：昭源黑體（Chiron Hei HK），字重 400、500、700。
- 數字與標註：JetBrains Mono，字重 400、500。

選昭源的原因：思源宋體與思源黑體的 900 字重缺簡體字與日文漢字（例如「撃、简、红、终、厅」），標題會粗細不一；昭源在同一字重下繁、簡、日文漢字都齊。

字體經 Google Fonts 載入，取代 `src/app/layout.tsx` 目前的思源字體連結。

### 4.2 顏色與主題

設計變數定義在全域 CSS，以 `<html>` 上的兩個屬性切換：

- `data-theme`：`dark` 或 `light`。沿用現有的 `ThemeContext` 與儲存鍵 `ctec-theme-preference`。
- `data-dim`：`overworld`、`nether`、`end`、`respawn`。決定強調色。

| 變數           | 暗色      | 亮色      |
| -------------- | --------- | --------- |
| 底色           | `#06080b` | `#eef2f5` |
| 文字           | `#f2f4f6` | `#0f1418` |
| 次要文字       | `#a3adb8` | `#414c57` |
| 強調色：主世界 | `#86cdff` | `#0b6fb5` |
| 強調色：地獄   | `#ff6a45` | `#c2330f` |
| 強調色：終界   | `#cdb0ff` | `#6234c4` |

亮色主題的原則：

- 照片不整片淡化。遮罩只在文字所在的一側是實心紙色，另一側保持照片原色。
- 直排的維度名稱站在照片上，自帶紙色底。
- 首頁的終界段落沒有白天：亮色主題捲到終界時介面轉為暗色，離開後轉回。內頁不套用這條規則。
- 寬度 860px 以下沒有空間留出乾淨的一側，遮罩改為由下往上。

### 4.3 版面常數

- 左右邊距：`clamp(20px, 6vw, 96px)`。
- 斷點：860px。以下隱藏頂列的章節連結與左側軌道，雙欄改單欄，直排標題改橫排。
- 宣言字級：`clamp(30px, 3.8vw, 64px)`。直排維度名稱：`clamp(40px, 5.2vw, 88px)`。首頁主標題：`clamp(56px, 13vh, 150px)`。

### 4.4 響應式

設計稿在桌面寬度檢查得最完整，手機只抽看過部分畫面。正式版把響應式當作驗收條件，不是收尾工作：每個元件完成時就要通過下列檢查，不留到最後統一修。

檢查的視窗尺寸：

| 類別     | 寬 × 高     |
| -------- | ----------- |
| 小手機   | 360 × 740   |
| 手機     | 390 × 844   |
| 手機橫向 | 844 × 390   |
| 平板直向 | 768 × 1024  |
| 平板橫向 | 1024 × 768  |
| 筆電     | 1280 × 720  |
| 桌面     | 1440 × 900  |
| 大桌面   | 1920 × 1080 |
| 超寬     | 2560 × 1440 |

每個尺寸都必須成立：

1. 沒有橫向捲動。
2. 文字不溢出容器、不互相重疊、不被固定的頂列蓋住。
3. 內文字級不小於 14px，標註不小於 11px。
4. 可點擊的元素觸控範圍不小於 44 × 44px。
5. 場景圖片以 `object-fit: cover` 填滿，主體不被裁到看不出是什麼；必要時為個別場景指定對焦位置。
6. 釘住畫面的段落（地獄設施）在矮視窗（高度 390）下內容仍完整可見，否則該尺寸改為不釘住。
7. 超寬螢幕下內容有最大寬度，文字行長不超過 40 個中文字。
8. 直排標題在 860px 以下改為橫排置於段落上方（4.3）；這是所有語言共用的規則。

斷點以內容為準：預設只有 860px 一個斷點，某個元件在上述任一尺寸不成立時，為該元件加斷點，而不是調整全站斷點。

### 4.5 設計原則：像一支影片

這個設計的目標是讓網站看起來像一支影片。這條原則高於設計稿，適用於所有設計，尤其是設計稿沒有涵蓋的部分。

- 訪客看得到的每一個狀態變化都是設計過的轉場。選單、面板、篩選、清單變動、主題切換、空白與錯誤狀態、滑鼠移入與目前所在項目，都不能瞬間出現、跳動或消失。
- 所有轉場使用同一套動態語言，也就是首頁的緩動曲線與時間長度。
- 沒有轉場的狀態切換是缺陷，不是可有可無的潤飾。
- 新增、修改或因審查而補上的東西，只要設計稿裡沒有（手機選單、錯誤區塊、載入狀態、新的控制項、版面的退路），都必須依這條原則設計它的轉場與外觀，並沿用設計稿的字體、間距、色彩與動態。「設計稿沒有這個元素」不是它沒有樣式或瞬間切換的理由。
- `prefers-reduced-motion: reduce` 時，位移與依序進場縮短成短暫的淡入，轉場結束後的畫面不變。

## 5. 架構

### 5.1 路由分組

用 Next.js 的路由群組把新舊頁面隔開，兩邊各有自己的外框，互不影響：

```
src/app/
  layout.tsx                 根版面：字體、主題初始化、分析腳本
  (dimensions)/              新外框
    layout.tsx
    page.tsx                 首頁
    survivalProgress/page.tsx
    member/page.tsx
  (legacy)/                  現有外框（NavigationBar、Footer、antd）
    layout.tsx
    join/ hardware/ openSource/ partner/ collaborative/
    redstoneCollection/ architectureCollection/
```

- 網址不變。`/survival/` 目前是進度頁的別名，保留並指向新的進度頁。
- `/home/` 目前與首頁相同，保留並指向新首頁。
- 新外框的連結指向尚未改版的頁面時，直接連到舊頁面。

### 5.2 元件

新元件放在 `src/components/dimensions/`，每個元件一個檔案、一個職責。

| 元件                                                                                             | 職責                                              | 依賴                |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------- | ------------------- |
| `DimensionProvider`                                                                              | 保存目前維度，寫入 `<html data-dim>`              | 無                  |
| `SiteBar`                                                                                        | 頂列：標誌、章節連結、主題切換、語言切換、Discord | `useTheme`、i18n    |
| `SiteFooter`                                                                                     | 頁尾連結與版權                                    | i18n                |
| `DimensionRail`                                                                                  | 首頁左側軌道，顯示捲動進度與目前維度              | `DimensionProvider` |
| `World`                                                                                          | 固定的舞台，包含所有場景圖層                      | 場景清單            |
| `useSceneTransitions`                                                                            | 依設定建立捲動驅動的換場時間軸                    | GSAP、ScrollTrigger |
| `Loader`                                                                                         | 區塊載入畫面                                      | 無                  |
| `PortalCanvas`                                                                                   | 傳送門動畫（程序產生，見 7.2）                    | 無                  |
| `Starfield`                                                                                      | 終界的星空                                        | 無                  |
| `Hero`、`DimensionOpening`、`WorkSection`、`NetherLedger`、`RankStatement`、`Credits`、`Respawn` | 首頁各段的內容                                    | i18n、資料          |
| `InnerHeader`                                                                                    | 內頁頁首：麵包屑、宣言、直排標題、背景圖          | i18n                |
| `Toolbar`                                                                                        | 內頁的篩選與搜尋列                                | 無                  |
| `ProgressLog`                                                                                    | 進度清單與固定的大年份                            | 進度資料            |
| `MemberRoster`                                                                                   | 成員名冊與搜尋                                    | 成員資料            |

樣式是純 CSS，放在 `src/styles/dimensions/`，所有規則都包在 `.dim` 範圍內，由設計稿直接移植。這樣新舊頁面的樣式互不影響，也不必把設計稿的樣式改寫成另一種寫法。新元件不使用 antd 與 styled-components。

### 5.3 場景與換場

場景清單是一份資料，放在 `src/constants/scenes.ts`：每個場景有識別碼、圖片來源、遮罩種類（側邊、寬側邊、底部、主視覺、翻轉）。

換場種類共六種，全部只移動整個圖層：

| 種類      | 做法                                           |
| --------- | ---------------------------------------------- |
| `push`    | 舊場景放大淡出，新場景由略大縮回並淡入         |
| `curtain` | 新圖層由下移入，內容反向等量位移，畫面像被揭開 |
| `slide`   | 同上，方向為由右向左                           |
| `portal`  | 傳送門畫布淡入蓋滿，中點切換場景，再淡出       |
| `fall`    | 舊場景旋轉縮小淡出，新場景由放大旋轉轉正       |
| `wake`    | 白色圖層淡入，中點切換，再淡出                 |

規則：

- 每個換場綁定一個觸發段落，從該段落頂端進入視窗底部開始，到頂端抵達視窗頂部結束。
- 連續的段落不使用同一種換場。
- 觸發點必須依頁面順序建立。地獄的設施段落會釘住畫面並增加捲動長度，排在它之後的觸發點若提早建立，位置會算錯。
- 平滑捲動由 Lenis 負責，動畫直接跟隨捲動位置，不再疊加第二層延遲。

### 5.4 減少動態

`prefers-reduced-motion: reduce` 時：

- 不載入 Lenis，不建立捲動驅動的時間軸。
- 場景在段落進入視窗中線時直接切換。
- 地獄設施段落不釘住，改為一般排列。
- 載入畫面直接消失。
- 出生點不載入影片，只顯示封面。

### 5.5 出生點的影片背景

團隊決定首頁頂部維持舊站的影片背景，不改成靜態的成員合照。這一點與設計稿不同，以本節為準。

- 影片與舊站相同：YouTube 影片，編號與起始秒數來自現有的 i18n 資料 `home.backgroundVideo`（目前是 `FCtztiDl_rE`，從第 9 秒開始）。靜音、自動播放、循環、不顯示控制列。
- 播放器放大並置中，讓標題列、控制列與標誌落在畫面之外，看起來像動態背景而不是嵌入的影片。尺寸沿用舊站：寬 `calc(150vh * 16 / 9)`、高 `100vh`、最小寬 `100vw`、最小高 `calc(120vw * 9 / 16)`。九個驗收視窗都不能露出播放器介面。
- 播放器不接受點擊與鍵盤焦點，對輔助技術隱藏。
- 成員合照是封面。載入畫面只等封面，不等影片。影片真正開始播放後，封面才淡出。影片被擋、離線或無法自動播放時，畫面停在封面。
- 以下情況不載入影片：減少動態、省流量模式、搜尋引擎爬蟲。
- 播放器在載入畫面結束後才建立，不參與首屏。
- 捲離出生點時暫停，回到頂部時繼續；分頁在背景時暫停。
- 標題、說明、按鈕與深淺主題的遮罩維持設計稿的處理，文字在動態畫面上必須清楚。
- 離開首頁時銷毀播放器。切換語言不會建立第二個播放器。

## 6. 資料

### 6.1 來源

沿用現有來源與 `useApi`：

- 進度：`{STATIC_DATA_API}/{語言}/survivalProgress.json`
- 成員：`{STATIC_DATA_API}/member.json`
- 開源專案數量：GitHub API（`GITHUB_API`）

圖片：`{STATIC_DATA_API}/images/…`。成員頭像：`mineskin.eu/helm/{uuid}/56.png`。

### 6.2 載入與失敗

- 首頁的數字有內建預設值（成員數、專案數），資料到了再更新；請求失敗時保留預設值，不顯示錯誤。
- 首頁的製作名單在資料到之前顯示空白區塊，失敗時隱藏成員段落並保留開源工具段落。
- 進度頁與成員頁在載入中顯示「載入中」，失敗時在清單位置顯示一句說明與「重新整理」。
- 篩選或搜尋沒有結果時，顯示一句說明下一步的提示。

### 6.3 進度的維度

資料目前沒有維度欄位。過渡做法：

- 在 `src/constants/progressDimensions.ts` 放一份對照表，以圖片識別碼（例如 `p14`）對應維度。
- 只收錄已確認的項目。初始內容為標題本身寫明維度的項目，以及已確認在終界的月宮。
- 沒有收錄的項目不顯示維度標籤，選擇特定維度篩選時不會出現，選「全部維度」時照常顯示。
- 首頁使用的場景（三件主世界作品、六個地獄設施、三件終界作品）直接寫在場景清單裡，不依賴這份對照表。

之後 `static-data` 若加入 `dimension` 欄位，優先採用資料裡的值，對照表作為後備。

## 7. 其他決定

### 7.1 多語系

- 沿用現有的 i18next 設定與語言偵測。
- 所有新文案加進三個語言檔的 `dimensions` 命名空間下：繁中為來源，簡中與英文在本期一併提供初版，之後由 Crowdin 維護。
- 專有名詞（成員名稱、專案名稱）不翻譯。

三種語言是同一個設計，不是三個版本。以下原則在所有語言都成立，任何語言都不另開版型：

1. **版面結構相同**：每一段的欄位、對齊、元素位置、換場種類與順序都不隨語言改變。
2. **首頁主標題是品牌名**：直排的「雲鎮工藝」在所有語言都維持中文，英文名稱由旁邊的 `CLOUD TOWN EXQUISITE CRAFT` 承擔。
3. **維度名稱一律直排在右側**：中文逐字直立；英文（`OVERWORLD`、`THE NETHER`、`THE END`）同樣直排，字母順時針轉 90 度，位置與字級規則不變。
4. **字級用同一組變數**：不為某個語言另訂字級。英文字串較長時靠換行與 `text-wrap: balance` 吸收；若仍放不下，改的是文案長度，不是版面。
5. **字體角色相同**：標題用襯線、內文用無襯線、數字與標註用等寬。昭源宋體與昭源黑體本身含拉丁字母，英文不另換字體。
6. **數字、日期、單位的格式相同**：日期一律 `YYYY.MM.DD`，數字用千分位。

文案長度的限制（寫翻譯時遵守）：宣言每行不超過英文 34 個字元；作品與設施名稱不超過 40 個字元；按鈕不超過 20 個字元。

### 7.2 傳送門動畫

設計稿使用了從遊戲檔案抽出的地獄門材質。本專案採 GPL 授權且公開，不把 Mojang 的圖檔放進版本庫。實作改為在畫布上以程序產生 16×9 格的紫色像素動畫，外觀接近但不使用原始材質。

`docs/design-demos/mc/` 不納入版本控制。

### 7.3 新增相依套件

- `gsap`（含 ScrollTrigger）
- `lenis`

兩者都只在首頁載入。出生點的影片沿用專案已有的 `youtube-iframe`，不新增套件。

### 7.4 效能

- 捲動驅動的動畫只改變 `transform` 與 `opacity`。不對滿版圖層使用 `clip-path`、`filter: blur` 或會觸發排版的屬性。
- 首屏只載入出生點場景的封面圖片；影片播放器與其餘場景的圖片在載入畫面結束後才開始抓取。
- 進度頁與成員頁的圖片使用延遲載入。

## 8. 測試

沿用 Playwright（`yarn test:e2e`，對靜態輸出執行）。

新增 `tests/dimensions.spec.ts`：

1. 首頁載入後載入畫面消失，主標題可見。
2. 捲到每個段落時，`<html data-dim>` 為預期的維度，且對應的場景圖層可見、其餘隱藏。這一項涵蓋 5.3 的觸發順序問題。
3. 主世界三件作品與終界三件作品各自顯示正確的場景。
4. 地獄設施段落捲到底時，顯示的是最後一個設施。
5. 亮色主題捲到終界時底色為暗色，離開後回到亮色。
6. 主題切換後換頁，主題保留。
7. 減少動態模式下，各段落內容可見且場景會切換。
8. 進度頁：項目數等於資料筆數；維度與年份篩選的結果數正確；無結果時出現提示。
9. 成員頁：人數等於資料筆數；搜尋會過濾；無結果時出現提示。
10. 響應式：對 4.4 的九個視窗尺寸，在首頁每一段、進度頁、成員頁各檢查一次，亮暗主題都跑：
    - 沒有橫向捲動。
    - 沒有文字溢出容器；主要文字元素的外框兩兩不重疊，也不與固定頂列重疊。
    - 可點擊元素的尺寸不小於 44 × 44px。
    - 內文與標註的計算後字級不低於下限。
    - 各尺寸留存截圖，供人工複查構圖與裁切。
11. 語言一致性，對繁中、簡中、英文各跑一次：
    - 頁面上沒有未翻譯的鍵（畫面文字不含 `dimensions.` 開頭的字串）。
    - 首頁每一段、進度頁、成員頁都沒有文字溢出容器或互相重疊。
    - 直排的維度名稱位於段落右側，寫入方向為直排。
    - 三種語言的段落數、場景順序、換場種類相同。

現有的 `tests/parity.spec.ts` 是拿線上版當基準比對。首頁、進度頁、成員頁改版後必然不同，從它的路由清單移除這三頁，其餘舊頁面繼續比對。

每個元件完成時另外以 `yarn lint`、`yarn typecheck`、`yarn build` 驗證。

## 9. 風險

- **白色主題在手機上效果有限**：窄螢幕只能整片淡化。已接受，列為第二期可再改進的項目。
- **動畫手感只能人工確認**：影格時間可以量，但節奏是否舒服需要實際捲動。每完成一個維度的段落就請團隊試一次。
- **新舊外框並存**：第一期結束時，新頁面與舊頁面的頂列和頁尾不同。這是暫時狀態，第二期結束後消失。
- **昭源是港式字形**：簡體讀者看到的共用字為港台寫法。若團隊在意，第二期可為簡體版另配思源宋體 SC。
