# 「三個維度」改版設計規格

日期：2026-10-07
分支：`feat/dimensions-redesign`
定稿的設計稿：`docs/design-demos/dimensions-v2.html`（首頁）、`docs/design-demos/progress.html`、`docs/design-demos/members.html`、`docs/design-demos/inner.css`

## 1. 目標

把雲鎮工藝官網改成一趟「走過 Minecraft 三個維度」的旅程。首頁是電影式的預告片，內頁是可查、可篩、可分享的資料頁。兩者共用同一套字體、維度色與頁首結構。

成功的標準：

- 首頁與設計稿在 1440 寬、暗色主題下逐段一致（章節、文案、轉場種類、順序）。
- 捲動動畫只用 `transform` 與 `opacity`，在作品區到地獄入口這段，超過 33ms 的影格不多於設計稿的量測值（319 格中 13 格）。
- 繁中、簡中、英文三種語言都沒有缺字或未翻譯的鍵，而且三種語言遵守同一套設計原則（見 7.1）。
- 亮、暗兩個主題都可用，選擇跨頁保留。
- `prefers-reduced-motion` 開啟時沒有捲動驅動的動畫，所有內容仍可讀。
- 從 360 到 2560 寬的九個視窗尺寸都通過響應式檢查（見 4.4）。

這次改版拆成兩期，本規格只涵蓋第一期。

- 內頁之間跨維度的轉場（傳送門、落下）。
- 網址帶語言的多語系路由。

## 4. 設計基礎

### 4.1 字體

- 標題：昭源宋體（Chiron Sung HK），字重 700、900。
- 內文：昭源黑體（Chiron Hei HK），字重 400、500、700。
- 數字與標註：JetBrains Mono，字重 400、500。

選昭源的原因：思源宋體與思源黑體的 900 字重缺簡體字與日文漢字（例如「撃、简、红、终、厅」），標題會粗細不一；昭源在同一字重下繁、簡、日文漢字都齊。

字體經 Google Fonts 載入，取代 `src/app/layout.tsx` 目前的思源字體連結。

### 4.2 顏色與主題

設計變數定義在全域 CSS，以 `<html>` 上的兩個屬性切換：

- `data-theme`：`dark` 或 `light`。沿用現有的 `ThemeContext` 與儲存鍵 `ctec-theme-preference`。
- `data-dim`：`overworld`、`nether`、`end`、`respawn`。決定強調色。

| 變數           | 暗色      | 亮色      |
| -------------- | --------- | --------- |
| 底色           | `#06080b` | `#eef2f5` |
| 文字           | `#f2f4f6` | `#0f1418` |
| 次要文字       | `#a3adb8` | `#414c57` |
| 強調色：主世界 | `#86cdff` | `#0b6fb5` |
| 強調色：地獄   | `#ff6a45` | `#c2330f` |
| 強調色：終界   | `#cdb0ff` | `#6234c4` |

上表的亮色值是「紙面」的顏色：沒有照片墊在底下的地方（內頁內文、工具列、頁尾、重生點底下的地面）。

亮色主題的原則（使用者決定，2026-10-14；取代原本「文字一側是實心紙色」的做法，示範在 `docs/design-demos/day-lab.css` 的 `subtitle`）：

- 白天不改變夜間的設計：照片滿版、文字站在場景的遮罩上、遮罩的形狀、版面，全部相同。白天只改遮罩的輕重。
- 照片上的字白天也是淺色字。照片不往紙色淡化，遮罩也不染色（不用維度色）。
- 白天的遮罩是純黑、很薄的一層（「字幕」）：文字自帶陰影，像電影字幕，照片保有白天的亮度。色標見下方「遮罩」。
- 照片上的文字顏色：文字 `#ffffff`、次要文字 `#eef2f5`、線 `rgba(255,255,255,0.45)`；強調色主世界 `#cfeaff`、地獄 `#ffd0c0`、終界 `#e6d8ff`。
- 文字陰影：`0 1px 2px rgba(0,0,0,0.75), 0 0 14px rgba(0,0,0,0.55), 0 0 40px rgba(0,0,0,0.4)`。實心按鈕（白底深字）不帶陰影。
- 直排的維度名稱和其他字一樣是淺色字，底下不墊紙條。
- 首頁的地獄與終界沒有白天：亮色主題捲到這兩個維度時，遮罩、文字與強調色都是夜間的值，離開後轉回。內頁不套用這條規則。
- 內頁標頭不分維度都用白天的字幕遮罩，只有強調色隨維度變；照片底部 56px 沉入紙面（標頭的文字都在這 56px 之上）。
- 寬度 860px 以下沒有空間留出乾淨的一側，遮罩改為由下往上。

遮罩（使用者規則，2026-10-12）：

- 遮罩就是設計稿 `docs/design-demos/dimensions-v3-video.html` 的遮罩：每個場景一層平滑漸層，形狀與色標照設計稿，各場景一致。
- 文字底下不另外加底（條狀底、局部漸層、淡色塊、當作底的陰影都不行）。
- 每張照片一個強度：`src/constants/scenes.ts` 的 `strength`（場景）與 `NETHER_STRENGTHS`（地獄六個設施），預設 1。遮罩的每個色標乘上這個數字，形狀不變；只有本身就暗的照片（開光影拍的）才低於 1。白天與夜間都套用。
- 860px 以下由下往上的遮罩，暗色主題的色標是 0.9 / 0.62 / 0.3（設計稿的 0.96 / 0.8 / 0.5 下每張照片都看不清楚）；亮色主題是 0.5 / 0.3 / 0.12。
- 亮色主題的色標（顏色 `0, 0, 0`）：側邊 0.42 / 0.28 / 0 / 0；底部 0.5 / 0.25 / 0；開場 0.4 / 0.2 / 0 / 0.2 / 0.35；重生點遠側（各組連結所在）0.2 / 0.2；內頁標頭與側邊相同。首頁頂列的霧是 `rgba(0,0,0,0.45)` 往下到 0。
- 自動化的對比度量測不適用於站在遮罩照片上的文字，也不是修改設計的理由。

### 4.3 版面常數

- 左右邊距：`clamp(20px, 6vw, 96px)`。
- 斷點：860px。以下隱藏頂列的章節連結與左側軌道，雙欄改單欄，直排標題改橫排。
- 宣言字級：`clamp(30px, 3.8vw, 64px)`。直排維度名稱：`clamp(40px, 5.2vw, 88px)`。首頁主標題：`clamp(56px, 13vh, 150px)`。

### 4.4 響應式

設計稿在桌面寬度檢查得最完整，手機只抽看過部分畫面。正式版把響應式當作驗收條件，不是收尾工作：每個元件完成時就要通過下列檢查，不留到最後統一修。

檢查的視窗尺寸：

| 類別     | 寬 × 高     |
| -------- | ----------- |
| 小手機   | 360 × 740   |
| 手機     | 390 × 844   |
| 手機橫向 | 844 × 390   |
| 平板直向 | 768 × 1024  |
| 平板橫向 | 1024 × 768  |
| 筆電     | 1280 × 720  |
| 桌面     | 1440 × 900  |
| 大桌面   | 1920 × 1080 |
| 超寬     | 2560 × 1440 |

每個尺寸都必須成立：

1. 沒有橫向捲動。
2. 文字不溢出容器、不互相重疊、不被固定的頂列蓋住。
3. 內文字級不小於 14px，標註不小於 11px。
4. 可點擊的元素觸控範圍不小於 44 × 44px。
5. 場景圖片以 `object-fit: cover` 填滿，主體不被裁到看不出是什麼；必要時為個別場景指定對焦位置。
6. 釘住畫面的段落（地獄設施）在矮視窗（高度 390）下內容仍完整可見，否則該尺寸改為不釘住。
7. 超寬螢幕下內容有最大寬度，文字行長不超過 40 個中文字。
8. 直排標題在 860px 以下改為橫排置於段落上方（4.3）；這是所有語言共用的規則。

斷點以內容為準：預設只有 860px 一個斷點，某個元件在上述任一尺寸不成立時，為該元件加斷點，而不是調整全站斷點。

### 4.5 設計原則：像一支影片

這個設計的目標是讓網站看起來像一支影片。這條原則高於設計稿，適用於所有設計，尤其是設計稿沒有涵蓋的部分。

- 訪客看得到的每一個狀態變化都是設計過的轉場。選單、面板、篩選、清單變動、主題切換、空白與錯誤狀態、滑鼠移入與目前所在項目，都不能瞬間出現、跳動或消失。
- 所有轉場使用同一套動態語言，也就是首頁的緩動曲線與時間長度。
- 沒有轉場的狀態切換是缺陷，不是可有可無的潤飾。
- 新增、修改或因審查而補上的東西，只要設計稿裡沒有（手機選單、錯誤區塊、載入狀態、新的控制項、版面的退路），都必須依這條原則設計它的轉場與外觀，並沿用設計稿的字體、間距、色彩與動態。「設計稿沒有這個元素」不是它沒有樣式或瞬間切換的理由。
- `prefers-reduced-motion: reduce` 時，位移與依序進場縮短成短暫的淡入，轉場結束後的畫面不變。

## 5. 架構

### 5.1 路由分組

用 Next.js 的路由群組把新舊頁面隔開，兩邊各有自己的外框，互不影響：

```
src/app/
  layout.tsx                 根版面：字體、主題初始化、分析腳本
  (dimensions)/              新外框
    layout.tsx
    page.tsx                 首頁
    survivalProgress/page.tsx
    member/page.tsx
  (legacy)/                  現有外框（NavigationBar、Footer、antd）
    layout.tsx
    join/ hardware/ openSource/ partner/ collaborative/
    redstoneCollection/ architectureCollection/
```

- 網址不變。`/survival/` 目前是進度頁的別名，保留並指向新的進度頁。
- `/home/` 目前與首頁相同，保留並指向新首頁。
- 新外框的連結指向尚未改版的頁面時，直接連到舊頁面。

### 5.2 元件

新元件放在 `src/components/dimensions/`，每個元件一個檔案、一個職責。

| 元件                                                                                             | 職責                                              | 依賴                |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------- | ------------------- |
| `DimensionProvider`                                                                              | 保存目前維度，寫入 `<html data-dim>`              | 無                  |
| `SiteBar`                                                                                        | 頂列：標誌、章節連結、主題切換、語言切換、Discord | `useTheme`、i18n    |
| `SiteFooter`                                                                                     | 頁尾連結與版權                                    | i18n                |
| `DimensionRail`                                                                                  | 首頁左側軌道，顯示捲動進度與目前維度              | `DimensionProvider` |
| `World`                                                                                          | 固定的舞台，包含所有場景圖層                      | 場景清單            |
| `useSceneTransitions`                                                                            | 依設定建立捲動驅動的換場時間軸                    | GSAP、ScrollTrigger |
| `Loader`                                                                                         | 區塊載入畫面                                      | 無                  |
| `PortalCanvas`                                                                                   | 傳送門動畫（程序產生，見 7.2）                    | 無                  |
| `Starfield`                                                                                      | 終界的星空                                        | 無                  |
| `Hero`、`DimensionOpening`、`WorkSection`、`NetherLedger`、`RankStatement`、`Credits`、`Respawn` | 首頁各段的內容                                    | i18n、資料          |
| `InnerHeader`                                                                                    | 內頁頁首：麵包屑、宣言、直排標題、背景圖          | i18n                |
| `Toolbar`                                                                                        | 內頁的篩選與搜尋列                                | 無                  |
| `ProgressLog`                                                                                    | 進度清單與固定的大年份                            | 進度資料            |
| `MemberRoster`                                                                                   | 成員名冊與搜尋                                    | 成員資料            |

樣式是純 CSS，放在 `src/styles/dimensions/`，所有規則都包在 `.dim` 範圍內，由設計稿直接移植。這樣新舊頁面的樣式互不影響，也不必把設計稿的樣式改寫成另一種寫法。新元件不使用 antd 與 styled-components。

### 5.3 場景與換場

場景清單是一份資料，放在 `src/constants/scenes.ts`：每個場景有識別碼、圖片來源、遮罩種類（側邊、寬側邊、底部、主視覺、翻轉）。

換場種類共五種，全部只移動整個圖層：

| 種類      | 做法                                                                                                                                   |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `push`    | 舊場景放大淡出，新場景由略大縮回並淡入                                                                                                 |
| `curtain` | 新圖層由下移入，內容反向等量位移，畫面像被揭開                                                                                         |
| `slide`   | 同上，方向為由右向左                                                                                                                   |
| `portal`  | 傳送門畫布淡入蓋滿，中點切換場景，再淡出。進入地獄用地獄門的紫色漩渦，進入終界用終界門的表面（近黑的底、青綠與淡白的光點分層緩慢飄移） |
| `wake`    | 白色圖層淡入，中點切換，再淡出                                                                                                         |

規則：

- 每個換場綁定一個觸發段落，從該段落頂端進入視窗底部開始，到頂端抵達視窗頂部結束。
- 連續的段落不使用同一種換場。唯一的例外是刻意的：進入地獄與進入終界都穿過傳送門，動作相同、表面不同（2026-10-11 使用者決定，取代原本進入終界的旋轉落入 `fall`，該種類已移除）。
- 觸發點必須依頁面順序建立。地獄的設施段落會釘住畫面並增加捲動長度，排在它之後的觸發點若提早建立，位置會算錯。
- 平滑捲動由 Lenis 負責，動畫直接跟隨捲動位置，不再疊加第二層延遲。
- 換場可以蓋在正在離開的段落文字上，但不能蓋在下一段的文字上：下一段的文字要等換場播完才出現（使用者決定，2026-10-15；團隊回饋「動畫沒播完字就出來了」）。換場的時機不變；維度開場（主世界、地獄、終界）的文字從段落頂端往下一個畫面才開始，換場結束時剛好在視窗底部，之後才捲進來。
- 維度開場的文字不停駐（釘住會讓捲動有卡住的感覺）。捲到靠近畫面上方時用起訖速度為零的緩動平順減速，幾乎靜止的那段距離裡宣言逐行由暗到亮，再平順恢復到捲動速度；段落底部加長同樣的距離，後面的內容位置不受影響（設計稿 `dimensions-v3-video.html`，2026-10-15 使用者從五個方案中選定）。
  - 減速段的長度：每行宣言三分之一屏，再加 0.4 屏；文字被帶下的距離是這段長度的 0.62。最慢時標題（860px 以下是橫排的維度名稱，以上是標籤）在畫面 20% 高。
  - 860px 以上，右側直排的維度名稱照原本以 `position: sticky` 停留，不跟著減速位移（同時位移會在停留開始與結束時跳動）；860px 以下名稱在最上方，跟著內容一起減速。
- 作品說明（主世界三件、終界兩件）等該作品的換場播完、段落頂端到達視窗頂部時，才在原位淡入上升。
- 製作名單從段落頂端往下一個畫面才開始，推進溶接到星空播完後才捲進來。
- 製作名單的最後一句「還沒結束。」在白光升起時停在畫面原位，白光蓋滿時在白色底下消去。
- 重生點是這條規則唯一的例外，因為白光是完全不透明的遮罩：重生點留在原本的位置，白光升起時它的文字在白色底下看不見，白光散開時才一項接一項淡入上升（2026-10-15 使用者選定）。半透明的換場（傳送門、推進溶接）仍然要等播完。
- 跳到一個維度（頂列、軌道）時落在開場標題最慢的位置，不落在段落頂端：段落頂端現在只有場景，文字在下一個畫面。

### 5.4 減少動態

`prefers-reduced-motion: reduce` 時：

- 不載入 Lenis，不建立捲動驅動的時間軸。
- 場景在段落進入視窗中線時直接切換。
- 地獄設施段落不釘住，改為一般排列。
- 載入畫面直接消失。

### 5.5 出生點的影片背景

團隊決定首頁頂部沿用舊站的影片作為背景。這一點與設計稿不同，以本節為準。這是出生點唯一的改動，標題、說明、按鈕與版面都維持設計稿。

- 影片與舊站相同，是週年紀念的介紹影片。編號與起始秒數來自現有的 i18n 資料 `home.backgroundVideo`。
- 做法與舊站相同：播放器放大並置中，讓播放器的介面落在畫面之外，看起來像動態背景。
- 不使用成員合照當封面。那張合照已經過時。
- 影片需要時間載入。從載入畫面到影片開始播放之間的轉場經設計稿 `docs/design-demos/dimensions-v3-video.html` 實驗後定案如下（2026-10-11）。

定案的做法（元件 `HeroVideo`，樣式在 `home.css` 的 `.vid`）：

- **一個放大的方框**：出生點場景裡有一個置中的 16:9 方框，寬度 `max(124vw, calc(124vh * 16 / 9))`，比畫面大，播放器上方的標題列與下方的控制列因此落在畫面之外。方框不接收指標事件，也不影響版面與捲軸。直向、橫向與桌面使用同一個尺寸（1440×900、390×844、844×390 實測都看不到播放器介面）。
- **封面是第一張圖**：方框裡下層是 YouTube 播放器，上層是影片自己的封面圖（`https://img.youtube.com/vi/<編號>/maxresdefault.jpg`，`object-fit: cover`）。封面寫在靜態輸出的標記裡，是首頁的第一張圖；載入畫面等的是封面與字體，不等影片。關閉指令碼時只看到封面，其他都不需要。
- **播放器參數**：靜音、自動播放、循環（`playlist` 為影片編號）、`controls: 0`、`playsinline: 1`、`fs: 0`、`iv_load_policy: 3`、`modestbranding: 1`、`rel: 0`、`disablekb: 1`、`start`；播放器來自 `www.youtube-nocookie.com`，封面圖以 `referrerPolicy="no-referrer"` 請求。`iframe` 帶 `tabindex="-1"`、`aria-hidden="true"` 與 `title`，不會取得焦點。
- **建立時機**：播放器只在瀏覽器裡建立，靜態輸出時不建立。訪客從頁首進站時立刻建立（在封面底下、載入畫面後面開始載入）；從其他段落進站（網址帶段落、回到上次的位置）時，要等出生點場景第一次出現才建立，看不到的影片不佔用流量。離開首頁時銷毀，回來時重建；切換語言不會產生第二個播放器。
- **不建立播放器的情況**：`prefers-reduced-motion: reduce`、瀏覽器要求節省流量（`navigator.connection.saveData`）、爬蟲（與舊站 `HeaderVideo` 相同的判斷）。這些情況下封面就是背景。
- **交接的時間**：載入畫面掀開後落在封面上，鏡頭由 1.3 緩回 1，標題照常進場。封面一直停留到下面兩個時間點中較晚的一個，再以 1.8 秒、`power2.inOut`、只改變透明度溶接成影片：
  1. 出生點的進場動畫結束（交接後約 3.1 秒）。溶接是獨立的一拍，不會發生在進場途中。
  2. 播放器回報「播放中」之後 4.2 秒（常數 `SETTLE_MS`）。YouTube 播放器開始播放後會在畫面中央顯示自己的按鈕約 3.5 秒，封面要蓋到它們消失。這個時間不得縮短到蓋不住按鈕。
- **只在看得到時播放**：出生點場景被換場關掉、或分頁被隱藏時暫停；回來時繼續播放。播放器被要求繼續播放時會再次顯示按鈕（實測約 4 秒），所以暫停時封面在沒有人看得到的時候立刻恢復，回來後播放器再次安定 4.2 秒才重新溶接。
- **影片結尾**：影片結束時播放器會出現黑畫面與載入圖示，重新開始時又顯示按鈕。因此在結尾前 2.3 秒封面以同樣的 1.8 秒溶接回來，等下一輪播放安定後再溶接成影片。
- **連不到 YouTube 的封面**（例如中國大陸的訪客）：出生點的第一張圖是哪一張，只由 `HeroVideo` 決定，並寫在圖片的 `data-cover` 上（`pending`、`youtube`、`local`）；載入畫面等到決定之後，再等被決定的那張圖。封面圖從指令碼接手起有 2 秒的時限（`COVER_BUDGET_MS`），請求失敗或逾時就改用版本庫裡的本地圖片（`LOCAL_COVER`，只在這時才下載），所以載入畫面不會等滿 6 秒後掀開在空白的底色上。兩張圖都遲到、載入畫面逾時掀開時，晚到的圖以 0.45 秒淡入，不會突然出現。只是慢、不是失敗的 YouTube 封面不會整趟都被捨棄：它在背後重新下載，等到靜止畫面不在訪客眼前時（影片正在播放、場景被關掉、分頁被隱藏）才換回來，之後就一直是它；絕不在眼前把一張靜止畫面換成另一張。請求失敗的封面不再重試。目前的本地圖片是舊站的成員合照 `public/assets/members/CTEC_Members.webp`，已經過時，只作為退路；團隊應提供一張取自影片的畫面，放在 `public/assets/homePage/`，並改 `HeroVideo.tsx` 的 `LOCAL_COVER`。關閉指令碼又連不到 YouTube 時沒有退路。
- **影片沒有播放**（被擋、離線、播放器載入失敗）：封面留著，不顯示錯誤。
- **測試不連 YouTube**：測試把封面換成版本庫裡的同一張圖（`tests/fixtures/hero-cover.jpg`），播放器指令碼換成會記錄呼叫的替身（`tests/helpers/video.ts`）。

已知且接受：使用 YouTube 時，載入畫面離開後封面會再停留數秒（實測在載入畫面完全離開後約 1.3 到 2.5 秒開始溶接），回到頁首時也一樣。這是為了蓋住播放器的按鈕，使用者已得知並選擇這個設計。

尚待決定：封面圖本身帶有大字的白色標題（「雲鎮工藝二周年」），夜間主題下出生點的說明文字壓在這些白字上時對比不足（見測試矩陣的 decision 8）。這是封面內容與設計稿版面的組合造成的，本期依指示不改動出生點的樣式。

## 6. 資料

### 6.1 來源

沿用現有來源與 `useApi`：

- 進度：`{STATIC_DATA_API}/{語言}/survivalProgress.json`
- 成員：`{STATIC_DATA_API}/member.json`
- 開源專案數量：GitHub API（`GITHUB_API`）

圖片：`{STATIC_DATA_API}/images/…`。成員頭像：`mineskin.eu/helm/{uuid}/56.png`。

### 6.2 載入與失敗

- 首頁的數字有內建預設值（成員數、專案數），資料到了再更新；請求失敗時保留預設值，不顯示錯誤。
- 首頁的製作名單在資料到之前顯示空白區塊，失敗時隱藏成員段落並保留開源工具段落。
- 進度頁與成員頁在載入中顯示「載入中」，失敗時在清單位置顯示一句說明與「重新整理」。
- 篩選或搜尋沒有結果時，顯示一句說明下一步的提示。

### 6.3 進度的維度

資料目前沒有維度欄位。過渡做法：

- 在 `src/constants/progressDimensions.ts` 放一份對照表，以圖片識別碼（例如 `p14`）對應維度。
- 只收錄已確認的項目。初始內容為標題本身寫明維度的項目，以及已確認在終界的月宮。
- 沒有收錄的項目不顯示維度標籤，選擇特定維度篩選時不會出現，選「全部維度」時照常顯示。
- 首頁使用的場景（三件主世界作品、六個地獄設施、三件終界作品）直接寫在場景清單裡，不依賴這份對照表。

之後 `static-data` 若加入 `dimension` 欄位，優先採用資料裡的值，對照表作為後備。

## 7. 其他決定

### 7.1 多語系

- 沿用現有的 i18next 設定與語言偵測。
- 所有新文案加進三個語言檔的 `dimensions` 命名空間下：繁中為來源，簡中與英文在本期一併提供初版，之後由 Crowdin 維護。
- 專有名詞（成員名稱、專案名稱）不翻譯。

三種語言是同一個設計，不是三個版本。以下原則在所有語言都成立，任何語言都不另開版型：

1. **版面結構相同**：每一段的欄位、對齊、元素位置、換場種類與順序都不隨語言改變。
2. **首頁主標題是品牌名**：直排的「雲鎮工藝」在所有語言都維持中文，英文名稱由旁邊的 `CLOUD TOWN EXQUISITE CRAFT` 承擔。
3. **維度名稱一律直排在右側**：中文逐字直立；英文（`OVERWORLD`、`THE NETHER`、`THE END`）同樣直排，字母順時針轉 90 度，位置與字級規則不變。
4. **字級用同一組變數**：不為某個語言另訂字級。英文字串較長時靠換行與 `text-wrap: balance` 吸收；若仍放不下，改的是文案長度，不是版面。
5. **字體角色相同**：標題用襯線、內文用無襯線、數字與標註用等寬。昭源宋體與昭源黑體本身含拉丁字母，英文不另換字體。
6. **數字、日期、單位的格式相同**：日期一律 `YYYY.MM.DD`，數字用千分位。

文案長度的限制（寫翻譯時遵守）：宣言每行不超過英文 34 個字元；作品與設施名稱不超過 40 個字元；按鈕不超過 20 個字元。

### 7.2 傳送門動畫

設計稿使用了從遊戲檔案抽出的地獄門材質。本專案採 GPL 授權且公開，不把 Mojang 的圖檔放進版本庫。實作改為在畫布上以程序產生 16×9 格的紫色像素動畫，外觀接近但不使用原始材質。終界門的表面同樣以程序產生（256×144 的像素畫布：近黑的底，五層深度的青、綠、淡白光點以不同速度飄移），不使用任何遊戲檔案。兩者共用同一個畫布元件 `PortalCanvas`，表面定義在 `src/lib/dimensions/portalSurfaces.ts`。

`docs/design-demos/mc/` 不納入版本控制。

### 7.3 新增相依套件

- `gsap`（含 ScrollTrigger）
- `lenis`

兩者都只在首頁載入。出生點的影片沿用專案已有的 `youtube-iframe`，不新增套件。

### 7.4 效能

- 捲動驅動的動畫只改變 `transform` 與 `opacity`。不對滿版圖層使用 `clip-path`、`filter: blur` 或會觸發排版的屬性。
- 其餘場景的圖片在載入畫面結束後才開始抓取。
- 進度頁與成員頁的圖片使用延遲載入。

## 8. 測試

沿用 Playwright（`yarn test:e2e`，對靜態輸出執行）。

新增 `tests/dimensions.spec.ts`：

1. 首頁載入後載入畫面消失，主標題可見。
2. 捲到每個段落時，`<html data-dim>` 為預期的維度，且對應的場景圖層可見、其餘隱藏。這一項涵蓋 5.3 的觸發順序問題。
3. 主世界三件作品與終界三件作品各自顯示正確的場景。
4. 地獄設施段落捲到底時，顯示的是最後一個設施。
5. 亮色主題捲到終界時底色為暗色，離開後回到亮色。
6. 主題切換後換頁，主題保留。
7. 減少動態模式下，各段落內容可見且場景會切換。
8. 進度頁：項目數等於資料筆數；維度與年份篩選的結果數正確；無結果時出現提示。
9. 成員頁：人數等於資料筆數；搜尋會過濾；無結果時出現提示。
10. 響應式：對 4.4 的九個視窗尺寸，在首頁每一段、進度頁、成員頁各檢查一次，亮暗主題都跑：
    - 沒有橫向捲動。
    - 沒有文字溢出容器；主要文字元素的外框兩兩不重疊，也不與固定頂列重疊。
    - 可點擊元素的尺寸不小於 44 × 44px。
    - 內文與標註的計算後字級不低於下限。
    - 各尺寸留存截圖，供人工複查構圖與裁切。
11. 語言一致性，對繁中、簡中、英文各跑一次：
    - 頁面上沒有未翻譯的鍵（畫面文字不含 `dimensions.` 開頭的字串）。
    - 首頁每一段、進度頁、成員頁都沒有文字溢出容器或互相重疊。
    - 直排的維度名稱位於段落右側，寫入方向為直排。
    - 三種語言的段落數、場景順序、換場種類相同。
12. 外框的轉場（4.5）：手機選單開啟時淡入並由上方落下，連結依序升起，總長不超過半秒；關閉時較快地淡出，淡出結束後才從畫面、焦點順序與輔助技術中移除。選單是蓋在頁面上的一層：開關前後，頁面寬度、捲軸、頂列各項的位置與捲動位置都不變，開啟期間頁面不捲動（首頁在段落中與地獄設施的固定段落內各測一次）。主題、選單按鈕的圖示與篩選、清單、空白、錯誤狀態的變化都有非零的轉場時間；減少動態模式下縮為不超過 120 毫秒的淡入淡出。

現有的 `tests/parity.spec.ts` 是拿線上版當基準比對。首頁、進度頁、成員頁改版後必然不同，從它的路由清單移除這三頁，其餘舊頁面繼續比對。

每個元件完成時另外以 `yarn lint`、`yarn typecheck`、`yarn build` 驗證。

## 9. 風險

- **白色主題在手機上效果有限**：窄螢幕只能整片淡化。已接受，列為第二期可再改進的項目。
- **動畫手感只能人工確認**：影格時間可以量，但節奏是否舒服需要實際捲動。每完成一個維度的段落就請團隊試一次。
- **新舊外框並存**：第一期結束時，新頁面與舊頁面的頂列和頁尾不同。這是暫時狀態，第二期結束後消失。
- **昭源是港式字形**：簡體讀者看到的共用字為港台寫法。若團隊在意，第二期可為簡體版另配思源宋體 SC。
